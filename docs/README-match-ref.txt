## how to use %(prog)s (and how to bypass or trick it in a pipeline fashion)

Input file (SAM) for %(prog)s is typically generated in a (snakemake) pipeline.
This code snippet shows how it's typically used, and how you could use it outside of such a pipeline.

    - minimap2 -ax sr /path/to/<multirefdatabase>/mmidx/apollo-species-refs.<hash>.mmidx *_R1.fastq *_R2.fastq > /path/to/input.sam}
    - %(prog)s /path/to/desired/OUTPFX /path/to/input.sam
    - this will generate following output files:
        - /path/to/desired/OUTPFX-match-ref-reference.tsv
        - /path/to/desired/OUTPFX-match-ref-taxid.tsv
        - /path/to/desired/OUTPFX-references.yml

Crucial here is that you choose a "true" mmidx index:

    - generated by the workflow implemented in the repo where %(prog)s is in
    - with all files (mmidx and corresponding dataframes!) at their designated locations
    - !important! at the moment of writing, only a single path to /path/to/<multirefdatabase> is supported
    - which is defined in config/referencedata.yaml

It's (highly) recommended to ignore (known) mitochondria in the species identification process!

    - %(prog)s /path/to/desired/OUTPFX /path/to/input.sam --excl-mito-tsv /path/to/<multirefdatabase>/reference_assembly_data.tsv
    - Main reason(s) to do this is:
        - not all species/strains have mitochondria added in the multi-reference database
        - mitochondrial DNA can be a considerable fraction of total PE fastq
        - and thus can bias %(prog)s towards favourable matching a species with a mitochondrion (in edge cases ...)
    - In the scenario of not having the /path/to/<multirefdatabase>/reference_assembly_data.tsv file:
        - use-case when (mis)using this repo in a highly customized fashion
        - consider using %(prog)s --excl-accessions A,B[,..] to force exclusion of concerning accessions

Optionally, when %(prog)s is part of a pipeline, one might want to:

    - bypass the %(prog)s functionality in total and/or
    - force to a particular reference, and use the assignment of %(prog)s as meta-data
    - see `%(prog)s --species-reference xxx --help` how to do this
    - this will generate the file /path/to/desired/OUTPFX-forced-references.yml
    - realize format is identical to "vanilla" /path/to/desired/OUTPFX-references.yml
    - this would allow you to implement your own pipeline logics concerning a bypass of %(prog)s
    - in case of an 'exterior' reference (not in /path/to/<multirefdatabase>), use the --custom flag
    - in the RIVM apollo-mapping pipeline, this feature is used to allow --custom-reference
